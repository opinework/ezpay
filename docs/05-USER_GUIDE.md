# 操作手册

部署和配置命令见[部署文档](./03-DEPLOY.md)，接口命令见[API](./04-API.md)，真实支付验收见[测试计划](./09-TESTPLAN.md)。

## 首次使用

1. 启动后访问 `/admin`。新数据库默认管理员 admin/admin123，应立即修改密码并配置稳定的 JWT secret。
2. 默认测试商户 PID 1001，登录密码 merchant123，支付密钥 test_key_123456；生产使用前修改密码并重置密钥。不要将这些默认凭据用于公网业务。
3. 配置公网 HTTPS site_url、订单有效期、通知次数、费率和汇率。YAML 与后台数据库配置的生效范围不同，见部署文档。
4. 创建商户并设置默认币种、回调地址；旧人民币接口商户应选 CNY。商户登录入口 `/merchant`，登录密码与支付签名密钥用途不同。
5. 配置一种实际可用的收款链路，创建小额订单验收到账、余额、回调后再开放业务。

现有管理员不会在重启时重置；历史商户缺少密码时可能初始化为 merchant123，应逐一检查。

## 收款方式

| 方式 | 必备条件 | 到账识别 |
| --- | --- | --- |
| 本地加密货币 | 启用链、有效 RPC、对应链钱包 | 地址、精确金额、确认数 |
| 支付宝 / 微信码支付（本地收款码） | 系统码或商户个人码、支持 v2 的监控端 | 商户、类型、精确金额及不可变事件 |
| V免签/易支付上游 | 上游地址、账号/密钥、启用通道 | 上游签名回调 |
| 官方支付宝/微信 | 已签约产品及官方密钥配置 | 官方签名通知或签名查单 |

付款 `type` 与实际通道独立。微信和支付宝可分别选择 `local` / `vmq` / `epay` / 对应官方通道，也可沿用全局默认。原接口无需新增通道字段，参数与签名见 [API](./04-API.md)。

## 支付方式使用步骤

下列步骤由管理员配置通道、商户配置收款信息，付款人在收银台完成付款。先用小额真实订单验证整条流程，再开放业务。

| 要使用的支付方式 | 操作指引 |
| --- | --- |
| USDT / TRX | [链上支付](#链上支付usdt--trx) |
| 支付宝 / 微信收款码 | [码支付](#支付宝微信码支付本地收款码) |
| 支付宝当面付 / 电脑网站 / 手机网站 | [支付宝官方支付](#支付宝官方支付) |
| 微信 Native / H5 | [微信官方支付](#微信官方支付) |
| V免签上游 | [V免签配置与付款](#v免签上游) |
| 彩虹易支付上游 | [易支付配置与付款](#彩虹易支付上游) |

### 下单与验收通用流程

1. 商户登录 `/merchant`，取得商户 PID 和支付密钥，在业务网站的易支付插件中配置 EzPay 站点地址、PID、密钥。
2. 按以下各节开通支付方式。人民币商品将商户默认币种设为 `CNY`，美元商品设为 `USD`；接口显式传入的 `currency` 优先于商户默认值。
3. 从业务网站创建订单；自行接入时使用 `/submit.php` 表单跳转，或 `/mapi.php` 获取 JSON 后打开 `payurl`。填写并签名 `pid,type,out_trade_no,name,money` 及所需币种、回调参数，完整签名规则见 [API](./04-API.md)。
4. 付款人核对支付方式、收款对象、币种、精确金额和有效期后付款。每次新建订单使用新的商户订单号。
5. 在商户「订单管理」核实订单变为已支付，并核对收款账户流水、费用和余额变化。使用个人钱包时，款项直接进入个人账户，手续费从商户余额处理，不能按系统钱包入账方式核对。
6. 核对业务网站已收到支付通知并完成订单处理。回调接收方需验签、校验订单和金额、幂等处理后返回纯文本 `success`；浏览器返回和用户点击「已付款」均不能替代服务端到账确认。

可先访问 `GET /api/payment-types?pid=实际商户PID` 检查可用支付方式。该接口反映配置可用性，真实到账仍需完成小额付款验收。

### 链上支付（USDT / TRX）

| 付款网络 | 付款资产 | 钱包类型 / YAML 配置名 | 下单 `type` |
| --- | --- | --- | --- |
| Tron | TRX | `trx` | `trx` |
| Tron TRC20 | USDT | `trc20` | `usdt_trc20` |
| Ethereum ERC20 | USDT | `erc20` | `usdt_erc20` |
| BNB Smart Chain BEP20 | USDT | `bep20` | `usdt_bep20` |
| Polygon | USDT | `polygon` | `usdt_polygon` |
| Optimism | USDT | `optimism` | `usdt_optimism` |
| Arbitrum | USDT | `arbitrum` | `usdt_arbitrum` |
| Base | USDT | `base` | `usdt_base` |
| Avalanche C-Chain | USDT | `avalanche` | `usdt_avalanche` |

所有网络按以下流程分别配置，钱包地址相同也要按网络分别添加：

1. 管理员在 `config.yaml` 的 `blockchain.<配置名>` 中启用对应链，配置可用 RPC、确认数和扫描间隔；USDT 链还需核对合约地址，TRX 原生币无需合约地址。修改 YAML 后重启服务。
2. 确认全局默认通道 `default_channel` 为 `local`，在管理后台「链路管理」检查目标链已启用、扫描正常。全局通道的配置接口见下方「上游通道配置入口」。
3. 管理员在「钱包管理」添加对应网络的系统钱包，或商户在自己的「钱包管理」添加个人钱包并启用。商户在「设置 → 钱包模式」选择实际要用的钱包；个人钱包需留有足够余额支付手续费。
4. 按表中 `type` 下单。USDT 商品通常使用 `currency=USD` 或 `USDT`；TRX 付款也可按 USD 标价，由系统换算应付 TRX。
5. 付款人使用收银台指定的网络，将指定资产转入展示的地址，精确支付展示金额。交易手续费另行准备，不能从应到账金额中扣除，也不能省略金额尾数。
6. 等待扫描发现交易并达到配置的确认数，再按通用流程核对订单和通知。订单有效期应覆盖付款和链上确认所需时间。

未到账时依次核对网络、资产合约、收款地址、实际到账金额、交易哈希、确认数、RPC 和扫描进度。不要将其他网络的同名资产视为已到账。

### 支付宝、微信码支付（本地收款码）

这里指上传支付宝或微信收款码、通过手机监控通知匹配订单的收款方式，使用 `local` 通道。

| 收款方式 | 添加钱包时选择 | 下单 `type` | 人民币标价 |
| --- | --- | --- | --- |
| 支付宝码支付 | 支付宝收款（`alipay`） | `alipay` | `currency=CNY` |
| 微信码支付 | 微信收款（`wechat`） | `wxpay` 或 `wechat` | `currency=CNY` |

1. 在「钱包管理 → 添加钱包」选择表中的类型，上传对应账户的有效收款码，填写标签并启用。管理员可添加系统收款码或指定商户的钱包；商户自己添加的是个人钱包。
2. 商户在「设置 → 钱包模式」选择「仅系统钱包」「仅个人钱包」或「两者同时使用」。混合模式优先个人钱包，无可用个人钱包时使用系统钱包；个人钱包收款前检查可用手续费余额。
3. 管理员在「系统设置 → 官方支付」区域，将「支付宝默认通道」或「微信默认通道」设为「本地收款码」；虽然入口位于该区域，这两项也用于选择本地和上游通道。在「链路管理」启用对应收款类型。
4. 商户打开「设置 → 监控客户端配置」，检查服务器地址，从配置二维码或显示字段取得地址、通讯密钥。该地址优先读取后台 `server_url`，未配置时从访问地址推导；反向代理部署应确认显示的是外部可访问地址。
5. 在收款手机上配置支持 **v2 监控协议**的客户端，导入配置二维码或填写服务器地址、商户通讯密钥，按客户端要求授权通知监听并保持运行。手机需能收到实际收款账户的通知；系统码应与实际订单商户的认证配置配套验收。
6. 客户端必须支持 HMAC-SHA256 认证、收款事件唯一标识和去重，旧版 MD5 推送不能用于收款确认。安装成功或心跳连通均不足以证明兼容，须用真实订单验证收款事件上报。
7. 按表中 `type` 创建人民币订单，付款人使用对应 APP 扫描收银台收款码，按展示的精确金额在有效期内付款。本地订单可能含识别尾数，不要自行改成商品原价或凑整。
8. 等待监控端上报并核实订单状态、实际流水及下游通知。支付宝和微信应各完成一次小额验收。

常见问题：

| 现象 | 检查与处理 |
| --- | --- |
| 无可用钱包 / 收款码未配置 | 检查钱包模式、归属、类型、启用状态、二维码是否上传成功及个人钱包手续费余额 |
| 心跳正常但不入账 | 确认客户端支持 v2 收款推送、已授权通知监听、收款账户与码一致；核对 API 日志中的推送业务结果 |
| 商户认证失败 | 核对通讯密钥；重置商户支付密钥后需重新配置监控端 |
| 请求时间无效或过期 | 校准手机和服务器时间 |
| 未找到唯一匹配订单 | 核对商户、微信/支付宝类型、精确金额、收款时间和订单有效期；保留流水并人工对账 |
| 已付款但订单过期 | 核实真实到账后人工处理，不要重放收款事件强行匹配新订单 |

商户只能自助确认属于自己的微信/支付宝个人钱包待支付或过期订单，操作会实际入账并通知，应先核实流水。系统钱包由管理员核实处理。

### 支付宝官方支付

1. 准备已开通目标支付产品的支付宝应用、应用 APPID、收款商户 PID、应用私钥和支付宝公钥。
2. 管理员打开「系统设置 → 官方支付」，填写公网 HTTPS 站点地址 `site_url`，确保 `/channel/notify/alipay_official` 可接收支付宝 POST 通知。
3. 填写上述支付宝配置，选择已开通的产品模式并启用支付宝官方通道。应用私钥用于本系统签名，支付宝公钥用于验证支付宝响应和通知，两者不可混用。
4. 将「支付宝默认通道」设为「支付宝官方」，保存配置。该设置只改变支付宝订单的实际通道，原客户端继续用 `type=alipay`。
5. 创建小额 `currency=CNY` 订单，按所选模式完成付款：

| 模式 | 付款人操作 |
| --- | --- |
| `f2f` 当面付扫码 | 打开收银台，用支付宝扫描动态二维码付款 |
| `page` 电脑网站支付 | 打开收银台付款入口，跳转支付宝电脑网站支付页面完成付款 |
| `wap` 手机网站支付 | 在手机打开收银台付款入口，进入支付宝手机网站支付流程 |

6. 官方签名通知或签名查单确认后，核对支付宝交易、EzPay 已支付状态及商户通知。无需为官方订单上传个人收款码或运行收款通知监控 APP。

官方通道使用精确 CNY 收款金额，不添加本地识别尾数；CNY 标价最多两位小数，跨币种订单由系统换算。更换支付模式只用于后续新单，验收应重新创建订单。

### 微信官方支付

1. 准备已开通目标产品的微信支付商户号 MCHID、APPID、商户证书序列号、商户私钥 PEM 和 32 字节 API v3 密钥。
2. 准备微信支付公钥 PEM 和对应公钥 ID（`PUB_KEY_ID_` 开头）；使用平台证书模式时填写平台证书 PEM。公钥模式与平台证书模式按实际接入选择，平台证书不能用商户证书代替。
3. 管理员在「系统设置 → 官方支付」填写公网 HTTPS `site_url` 及上述微信配置，确保 `/channel/notify/wechat_official` 可接收微信 POST 通知。
4. 选择已开通的微信产品模式、启用微信官方通道，将「微信默认通道」设为「微信官方」并保存。
5. 创建 `type=wxpay`（或 `wechat`）、`currency=CNY` 的小额订单，按所选模式付款：

| 模式 | 付款人操作 |
| --- | --- |
| `native` Native 扫码 | 打开收银台，用微信扫描动态二维码付款 |
| `h5` H5 支付 | 在手机浏览器打开收银台付款入口，按跳转流程唤起微信付款 |

6. 核对微信支付交易、EzPay 订单及商户通知。官方模式同样无需上传个人收款码或运行监控 APP，金额精度规则与支付宝官方一致。

官方支付配置保存时会检查密钥格式和必填项，保存成功不代表产品权限或通知网络已通过验收。失败时检查模式是否已开通、APPID 与商户号是否匹配、密钥/证书及回调可达性。停用官方通道后仍应保留旧单处理所需配置，直到完成对账。当前未接入官方退款接口，不能通过 EzPay 发起退款。

### 上游通道配置入口

当前管理页面提供微信、支付宝的通道选择；上游地址和密钥等使用管理员配置 API `POST /admin/api/configs` 保存，配置值均为字符串，需管理员 Bearer Token。登录方法见 [API 鉴权](./04-API.md#鉴权与响应)。

以下为字段示例，替换实际地址和凭据后提交；只配置准备启用的上游。`site_url` 是 EzPay 公网 HTTPS 地址，`api_url` 是上游服务根地址，不要附加 `/createOrder` 或 `/mapi.php`。

```json
{
  "site_url": "https://pay.example.com",
  "channel_vmq_enabled": "1",
  "channel_vmq_api_url": "https://vmq.example.com",
  "channel_vmq_key": "替换为V免签通讯密钥",
  "channel_epay_enabled": "1",
  "channel_epay_api_url": "https://epay.example.com",
  "channel_epay_pay_id": "替换为上游商户PID",
  "channel_epay_key": "替换为上游商户密钥"
}
```

微信、支付宝分别通过 `payment_channel_wechat` 和 `payment_channel_alipay` 选择 `local`、`vmq`、`epay` 或各自官方通道。全局默认 `default_channel` 可设为 `local`、`vmq` 或 `epay`；切换全局默认会影响未独立指定通道的支付方式，应先核对上游支持范围。本地链上收款使用 `default_channel=local`，微信、支付宝可单独选上游。

### V免签上游

1. 准备可用的 V免签上游服务，确认其已开通需要的收款方式，取得根地址和通讯密钥。
2. 按上一节保存 `channel_vmq_api_url`、`channel_vmq_key`、`channel_vmq_enabled=1` 及本地 `site_url`。
3. 在管理后台分别将「支付宝默认通道」或「微信默认通道」设为「V免签」。若要使用上游链上支付，需确认上游支持并配置全局默认；当前适配映射微信为 1、支付宝为 2、TRC20 为 3、ERC20 为 4、BEP20 为 5，不应使用它转发 Polygon、Optimism、Arbitrum、Base 等其他链。
4. 使用对应 `type` 从 EzPay 下单并进入收银台，按上游付款页面展示的金额和方式完成付款。微信、支付宝人民币商品使用 `currency=CNY`。
5. 确认上游可访问 EzPay 的 `/channel/notify/vmq`，核对上游签名回调、EzPay 已支付状态及下游商户通知。只在上游看到支付成功，尚不能认为本地通知流程已完成。

EzPay 会向上游 `/createOrder` 创建订单，回调验签使用配置的通讯密钥。本地码支付的手机 v2 监控推送与这里的上游签名回调是不同接口。

### 彩虹易支付上游

1. 在上游开通要使用的支付方式，取得上游服务根地址、商户 PID 和商户密钥。
2. 按「上游通道配置入口」保存 `channel_epay_api_url`、`channel_epay_pay_id`、`channel_epay_key`、`channel_epay_enabled=1` 及本地 `site_url`。
3. 将「支付宝默认通道」或「微信默认通道」设为「易支付上游」。其他支付方式如需走上游，先核对其 `type`、币种及金额字段兼容性，再配置全局默认。
4. 从 EzPay 创建订单，打开本地收银台并按上游付款入口完成付款。上游必须支持本系统发送的支付类型与币种，不能仅凭“易支付兼容”判断所有链路可用。
5. 确保上游可访问 `/channel/notify/epay`；核对上游 PID、签名、交易状态、订单和金额校验通过，本地订单变为已支付且业务网站收到通知。

EzPay 向上游 `/mapi.php` 下单。若上游显示成功而本地未更新，检查回调 URL、上游密钥/PID、支付类型及金额、币种是否一致，保留本地和上游订单号对账。

## 钱包与费用

- 系统钱包归属 merchant_id=0；个人钱包归属于具体商户。模式 1 仅系统、2 仅个人、3 混合。
- 钱包地址必须与链一致；EVM 地址比较可忽略大小写，TRON 地址区分大小写，不要自行统一转换。
- 二维码图片不等于动态支付链接；本地收款码用户应按收银台显示的精确金额付款。
- 商户余额、冻结金额、结算金额、提现均为 USD。原标价 money/currency 与实付 actual_amount/pay_currency 不可混用。
- 系统钱包费用从结算中扣；个人钱包费用涉及商户预存余额/冻结，创建订单前检查可用余额。到账、取消和过期应核对冻结释放结果。
- 跨币种付款涉及市场汇率及买入浮动；rate_buy_float/rate_sell_float 使用小数比例，0.02 表示 2%。同币种及 USD/USDT 同锚定支付不叠加跨币种浮动。

## 订单处理

状态：0 待支付、1 已支付、2 已过期、3 已取消。通知状态与支付状态独立，已到账但商户未发货应先检查通知日志，而不是再次补款。

排查顺序：确认商户订单号/平台订单号 → 核实付款链及金额 → 检查链日志/监控事件/官方交易 → 检查订单和余额 → 检查下游通知。浏览器返回、用户点击“已付款”或监控心跳均不能单独证明到账。

商户自助确认仅适用于自己的微信/支付宝个人钱包待支付或过期订单，会实际入账并通知；确认前必须人工核实。系统钱包由管理员核实处理，官方订单需要官方签名查单。

官方订单取消先查单并请求官方关闭；网络失败不能视为已经关闭。延迟通知若官方付款发生在有效期内可补偿过期订单；取消订单及超时付款应人工对账。官方停用只阻止新单，旧单仍需处理。

管理员可导出订单、查看 API/链上日志、手动重试已支付订单通知。手动通知会重置重试预算，接收系统必须幂等。清理无效订单是显式操作，并非 YAML cleanup_hours 定时任务；不要删除支付账本来解决重复回调。

## 提现闭环

1. 商户添加提现地址：当前支持 BEP20/TRC20/Polygon/Optimism，检查链和地址后提交审核。
2. 管理员审核地址；商户使用已审核地址发起申请，默认最低 50 USD、手续费 1 USD。
3. 管理员审核提现，线下或外部钱包完成实际打款，再将申请标记完成；系统没有自动代签链上转账。
4. 驳回需填写原因并核对余额恢复；完成需留存转账记录。地址更新仅 label/is_default，实际地址变更需新建审核。

## 通知、APP 与日常维护

商户机器人绑定、通知开关与管理员机器人是两套配置，见[Telegram](./07-TELEGRAM.md)。service_telegram/service_discord 仅为客服入口。

后台 APP 版本管理可上传 APK、设置版本号/更新说明/强制更新；服务端只分发文件，不构建 Android APP。上传后检查版本接口和真实下载，勿把监控端安装成功等同于收款监听已授权。

```bash
curl -fsS https://pay.example.com/health
curl -fsS https://pay.example.com/health/detail
sudo systemctl status ezpay --no-pager
sudo journalctl -u ezpay --since '1 hour ago' --no-pager
```

每日检查异常订单、通知失败、余额冻结、提现待办、链确认进度、官方证书有效期及备份恢复能力。备份必须同时包含订单、余额、事件去重表、官方/上游支付映射和扫描进度，操作步骤见部署文档。
